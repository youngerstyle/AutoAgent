# TEAMHQ 工作空间设计 V2

## 1. 设计结论

TEAMHQ 不是给旧运行台换导航和配色，而是把 Agent、Ticket 和 Mission 的运行事实组织成一间真正可进入的数字办公室。

- 三大 Engine 与既有 API 保持独立，前端不替 Agent 判断、不替 Ticket 流转。
- 办公室是默认主场景，项目、人才、模型和运营是独立工作台。
- 用户首先看到团队正在做什么、谁在工作、谁需要自己，而不是日志和配置表单。
- 原始事件、协议与 JSON 是审计细节，只在用户主动展开时出现。

## 2. 全局空间框架

### 2.1 左侧空间导航

使用固定垂直 Rail，五个入口始终可达：

1. 办公室
2. 项目
3. 人才
4. 模型
5. 运营

Rail 底部只显示当前平台状态，不展示业务判断。

### 2.2 项目上下文栏

顶部 Context Bar 始终展示：

- 当前 Workspace，可直接切换。
- 当前 Mission，未发布时显示明确空状态。
- 当前 Phase 与真实运行状态。

管理页面不重复创建一套项目选择器。

## 3. 办公室

### 3.1 Mission 指挥台

办公室顶部是一条紧凑工作带：

- 当前 Mission 或新目标入口。
- Plan 版本、Ticket 完成度和团队人数。
- 全局补充/新目标输入。
- 暂停、继续和停止控制。

它是任务入口，不是另一套流程引擎。

### 3.2 团队平面

中央区域按真实办公室表达，而不是头像卡片墙：

- 负责人办公室。
- 计划与设计区。
- 交付工作区。
- 项目协作桌。
- 每位 Agent 以工位出现，显示运行、等待 Human、空闲或失败。

点击工位只改变当前查看对象，不改变 Engine 状态。

### 3.3 工作动态

右侧 Feed 只展示可快速扫描的事实摘要：

- Agent 开始/完成一次 Turn。
- Ticket 被领取、交付、阻塞或完成。
- Human 消息被接收。
- 失败与待人工处理。

运行记录和原始工单通过图标切换。提示词、输出协议和 JSON 不直接铺在摘要层。

### 3.4 对话坞

底部是当前 Agent 的完整 Thread：

- 选择 Agent 后立即进入独立对话。
- 文本、图片和文件严格按时间进入同一个 Thread。
- Agent 正在运行时，新消息排入下一 Turn，不并发创建另一会话。
- Human-in-loop 快捷按钮等价于普通消息，不是代码判断。

## 4. 管理工作台

### 4.1 项目

- 左侧创建和选择 Workspace。
- 右侧查看当前 Mission、Plan、Ticket 和项目团队实例。
- 创建 Workspace 不自动发布 Mission。
- 删除项目使用显式确认，并可选择是否删除本地目录。

### 4.2 人才

- 管理跨项目长期存在的 Agent Profile。
- 顺序固定为 Soul、Identity、Agent。
- 配置默认模型、Skill 和工具权限。
- 项目实例只做覆盖，不修改全局档案。

### 4.3 模型

- 管理 Provider、模型、上下文窗口和能力。
- 支持新增、改名、保存与设为默认。
- 不根据角色猜测模型或工具。

### 4.4 运营

- 汇总 Agent Engine、Ticket Engine、Mission Control 的运行事实。
- 展示项目数、运行成员、待处理事项、Ticket 数和失败事件。
- 不参与业务调度，不创造第四套状态。

## 5. 视觉系统

- 工作界面以白、浅灰、炭黑为基础，搭配克制的青绿；运行绿、等待黄、失败红只用于状态。
- Rail 使用明亮桌面应用风格，导航选中态是安静的色块，不使用老式描边按钮。
- 办公室不是流程图：完整办公空间图片承载桌椅、会议区、咖啡角和动线，Agent 是叠加在真实工位上的人物，而不是矩形卡片或几何占位符。
- 每位 Agent 使用岗位图标、人物身体、状态点和短气泡组成稳定角色；运行时轻微呼吸，等待 Human 时使用黄色状态点和感叹号，失败时使用红色状态。
- 工作动态使用紧凑时间线；Agent 对话是底部 Thread 抽屉，不抢占办公室主场景。
- 圆角只用于导航选中态、输入区、状态气泡和独立实体，不用卡片包裹整段页面。
- 不使用装饰性渐变光球、营销式大标题或纯粹为了“科技感”的网格。
- `1280×720` 和 `1600×900` 无页面级横向滚动；长文本在局部容器内处理。

## 6. 验收标准

1. 第一眼能识别为团队办公室，而不是日志控制台。
2. 当前项目、Mission、Agent 状态和待人工事项不需要翻找。
3. 点击任意 Agent 可以查看完整 Thread 并发送消息。
4. 五个顶层工作区的职责和布局不同，不是同一张旧页面换标题。
5. 所有展示均来自真实 Engine 数据，前端不写死角色流程。
6. 既有 Engine 测试、生产构建和真实浏览器验收全部通过。
