# TEAMHQ 工作空间设计

## 1. 产品目标

TEAMHQ 是自动化团队的工作空间，不是三大 Engine 之外的第四套流程系统。

- Agent Engine 决定员工正在做什么、说什么、使用什么工具。
- Ticket Engine 决定工作项、依赖、负责人和状态。
- Mission Control 决定 Mission、Plan、Ticket 与 Agent 之间的协调。
- TEAMHQ 只负责把这些事实组织成可观察、可进入、可操作的办公室。

界面不能根据角色名称猜测流程，也不能替 Agent 判断完成、返工或验收。

## 2. 顶层信息架构

### 2.1 办公室

面向当前项目的实时协作空间。

- 左侧：当前项目、Mission/Ticket 摘要和团队成员导航。
- 中央：员工工位、运行状态、当前工作和注意标记。
- 底部：选中 Agent 的完整对话，进入 human-in-loop。
- 右侧：按时间排序的工作动态与原始工单。

办公室只投影 Engine 状态。动画、工位和气泡不得改变任务状态。

### 2.2 项目

管理 Workspace 及其长期资产。

- 项目列表与创建项目。
- 当前 Mission、Plan、Ticket 和运行状态概览。
- 项目团队实例、模型、Skill 与工具权限。
- 项目路径、安全策略和删除操作。

创建项目是创建 Workspace，不等于创建 Mission。用户可以创建空项目，再进入办公室描述目标。

### 2.3 人才中心

管理跨项目长期存在的 Agent Profile。

- Soul：稳定个性、动机与行为倾向。
- Identity：岗位职责、授权和组织关系。
- Agent：能力、方法、工具使用和交付习惯。
- 默认 Skill、模型与工具权限。
- 项目实例继承默认值，并可做显式覆盖。

人才中心不保存项目运行状态。

### 2.4 模型服务

管理 Provider 与模型配置。

- OpenAI、Anthropic 等 Provider。
- 模型名称、上下文窗口、推理能力、图片能力。
- 默认配置和连通性信息。

### 2.5 系统运营

面向平台操作者展示跨 Engine 的运行健康度。

- 当前 Workspace、Agent、Ticket 和待人工介入数量。
- 最近事件和异常摘要。
- Engine 边界说明与运行状态。
- 后续承载预算、成本、队列和审计检索。

系统运营不参与业务调度。

## 3. 关键交互

### 3.1 Agent 状态

- 绿色：Agent 正在执行 Turn。
- 黄色：Agent 或 Ticket 明确等待 Human。
- 灰色：空闲或排队。
- 红色：执行失败，需要查看原因。

状态颜色必须来自真实状态，不能根据聊天内容或关键字推测。

### 3.2 Human-in-loop

点击任意 Agent 后，底部打开其独立 Thread。

- 普通状态下也允许发送消息。
- Agent 正在运行时，新消息进入该 Agent 的顺序队列，在下一 Turn 处理。
- 快捷按钮只是预填或发送普通消息，不是平台状态判断。
- 图片和文件与文本一样，按时间顺序进入 Thread。

### 3.3 项目与 Mission

- Workspace 是项目容器。
- 一个功能目标创建一条 Mission。
- 一条 Mission 同一时刻只有一个有效 Plan。
- Ticket 是 Plan 中可调度的工作节点。
- 已完成 Ticket 保留历史并退出调度。

TEAMHQ 展示这些关系，不在前端重建关系。

## 4. 布局与视觉规则

- 顶栏固定为全局导航、当前项目和全局状态。
- 办公室采用三列可调宽布局，中间对话区可调高度。
- 管理页面使用紧凑的主从布局，不嵌套装饰性卡片。
- 列表、表单和工作台保持 6px 以内圆角。
- 所有长文本必须换行或截断，不产生页面级横向滚动。
- 运行记录默认收纳，按时间正序展示，并自动滚动到最新内容。
- 界面文字使用中文；原始协议、事件类型和 JSON 只在展开详情中显示。

## 5. 页面验收标准

1. 五个顶层页面职责清楚，用户能判断当前所在位置。
2. 创建项目、删除项目、编辑 Agent Profile、配置项目 Agent、配置模型均可完成。
3. 办公室可以选择 Agent、查看状态、发送文本/图片/文件并看到历史。
4. 系统运营能展示当前真实数据，不使用演示假数据。
5. 1280x720 与 1600x900 下无页面级横向滚动、遮挡或不可达操作。
6. 所有既有 Engine 测试继续通过，前端不新增流程判断。
